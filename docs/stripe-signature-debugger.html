Why is my webhook signature failing?

A webhook signature debugger for Stripe, GitHub, Shopify and Slack, running entirely in your browser. Paste the three things constructEvent takes and it computes the same HMAC Stripe does, then tells you which part doesn’t line up — usually the body, not the secret. You can also generate a signed curl command to test a handler locally.

Nothing leaves your browser. The HMAC is computed locally with the Web Crypto API. There is no server, no analytics, no network request. View source, or read it on GitHub — it’s one file.

Writing a test for your webhook handler? Pick an event, and this builds a realistic payload signed with your test secret — as a curl command you can paste straight into a terminal.

The four things that are usually wrong

  • You verified a re-serialised body. Frameworks parse JSON for you. Re-stringifying changes whitespace and key order, so the HMAC differs. Read the raw text: in Next.js await request.text(), in Express express.raw({type:'application/json'}).
  • You used the wrong secret. The signing secret is per-endpoint and starts with whsec_. The one printed by stripe listen is different from the one in the Dashboard for your deployed endpoint — using the CLI's secret in production is a classic.
  • A proxy rewrote the body. Some gateways re-encode or strip a trailing newline. If the signature works locally but not in production, suspect what sits in front of your app.
  • The timestamp is outside tolerance. The signature can be valid while constructEvent still throws, because it also enforces a default 5-minute window against replay. Replaying an old captured request will fail for this reason alone.

What correct verification looks like

const event = stripe.webhooks.constructEvent(
  await request.text(),                       // raw bytes, not a re-serialised object
  request.headers.get("stripe-signature"),
  process.env.STRIPE_WEBHOOK_SECRET           // whsec_..., per endpoint
);
